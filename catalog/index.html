1. Что такое формат .fptools?

Формат .fptools — это стандартизированный JSON-контейнер. Он используется для обмена настройками, шаблонами, автоответами и правилами ИИ между пользователями приложения FunPay Tools. Файл имеет MIME-тип application/json, но сохраняется с расширением .fptools для ассоциации с приложением.

2. Структура файла (JSON)

{
  "version": 1,
  "author": "Nickname",
  "description": "Описание пака",
  "data": {
    "templates": [...],
    "auto_responses": [...],
    "review_reply_settings": {...},
    "greeting_settings": {...},
    "feedback_bonus_settings": {...}
  }
}

3. Модели данных (data)

Шаблоны сообщений (templates)

Массив объектов. Ключи:

  • id (String) - Уникальный UUID
  • name (String) - Название кнопки шаблона
  • text (String) - Текст. Поддерживает $username, $date, $welcome
  • imageUri (String | null) - Опционально URI картинки (лучше не передавать в паках)
  • imageFirst (Boolean) - Отправлять картинку до текста

Автоответы (auto_responses)

Массив объектов. Ключи:

  • trigger (String) - Слово или фраза для реакции
  • response (String) - Текст ответа
  • exactMatch (Boolean) - Точное совпадение
  • caseSensitive (Boolean) - Учет регистра
  • callMode (Boolean) - Режим вызова (звонок продавцу)
  • callStyle (String) - "notification" или "fullscreen"
  • callAutoReplyTextRaw (String | null) - Текст, пока идет звонок

Ответы на отзывы (review_reply_settings)

Объект. Ключи:

  • enabled (Boolean)
  • useAi (Boolean) - Использовать ли нейросеть
  • aiLength (Int 1-10) - Объем генерируемого ответа
  • aiIncludeLotName / aiIncludeDate (Boolean)
  • aiWritingStyle (String) - Стиль (дерзко, мило и т.д.)
  • aiCustomInstruction (String) - Промпт для ИИ
  • manualTemplates (Object) - Карта "оценка" -> "ответ", напр: {"5":"Спасибо", "1":"Сам дурак"}
  • disabledStars (Array of Int) - Оценки, на которые бот НЕ отвечает

4. Принцип "QR-кода" (Fault-Tolerance) при Импорте

Главное правило парсера в приложении: выживает сильнейший. При импорте файла приложение не должно падать, если файл частично поврежден.

Алгоритм парсинга:

  1. Читаем блок data.
  2. Входим в цикл по массиву (например, templates).
  3. Оборачиваем чтение каждого элемента в try-catch.
  4. Если 2-й шаблон не содержит обязательного поля text — ловим Exception, пропускаем 2-й шаблон, но успешно сохраняем 1-й и 3-й.

5. Экспорт из приложения

При нажатии "Поделиться" приложение собирает все выбранные пользователем коллекции, сериализует их в JSON через GSON, добавляет оболочку (version, author) и сохраняет в файл.
