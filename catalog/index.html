Спецификация .fptools и API

×

1. Что такое формат .fptools?

Формат .fptools — это стандартизированный JSON-контейнер. Он используется для обмена настройками, шаблонами, автоответами и правилами ИИ между пользователями приложения FunPay Tools. Файл имеет структуру обычного JSON, но сохраняется с расширением .fptools для привязки к приложению Android/PC.

2. Структура корневого объекта

{
  "version": 1,
  "author": "Nickname",
  "description": "Описание пака",
  "data": { ... }
}

3. Модели данных (внутри объекта data)

Шаблоны сообщений (templates)

Массив объектов. Ключи:

  • id (String) — Уникальный UUID (генерируется приложением).
  • name (String) — Название кнопки шаблона.
  • text (String) — Текст сообщения. Поддерживает плейсхолдеры: $username, $date, $welcome.
  • imageUri (String | null) — URI картинки. (При экспорте в публичный каталог локальные пути вырезаются).
  • imageFirst (Boolean) — Порядок отправки: true = картинка, затем текст.

Автоответы (auto_responses)

Массив объектов. Ключи:

  • trigger (String) — Слово или фраза, на которую реагирует бот.
  • response (String) — Текст ответа бота.
  • exactMatch (Boolean) — true если требуется точное совпадение фразы (а не вхождение).
  • caseSensitive (Boolean) — Учет регистра букв (А ≠ а).
  • callMode (Boolean) — Включен ли режим "вызова продавца" (будильник).
  • callStyle (String) — Стиль вызова: "notification" или "fullscreen".
  • callAutoReplyTextRaw (String | null) — Сообщение, которое отправляется покупателю во время "дозвона".

Настройки ответов на отзывы (review_reply_settings)

Объект. Ключи:

  • enabled (Boolean) — Включена ли функция в целом.
  • useAi (Boolean) — true = генерация через ИИ, false = по шаблонам.
  • aiLength (Int, 1-10) — Объем генерируемого ответа.
  • aiIncludeLotName / aiIncludeDate (Boolean) — Инструкция ИИ на упоминание лота/даты.
  • aiWritingStyle (String) — Тон ответа (например, "Дерзкий", "Милый", "Официальный").
  • aiCustomInstruction (String) — Дополнительный кастомный промпт.
  • aiFallbackText (String) — Текст при ошибке серверов ИИ.
  • manualTemplates (Object) — Карта: оценка -> ответ. Пример: {"5":"Спасибо", "1":"Сам дурак"}.
  • disabledStars (Array of Int) — Массив оценок (1-5), на которые бот НЕ должен отвечать вообще.

Приветствие (greeting_settings)

Объект. Ключи:

  • enabled (Boolean) — Включено ли приветствие.
  • text (String) — Текст приветствия.
  • cooldownHours (Int) — Задержка (в часах) перед повторным приветствием одного и того же юзера.
  • ignoreSystemMessages (Boolean) — Не реагировать, если покупатель ничего не написал, а просто сделал заказ (системное сообщение).

4. Экспорт и Импорт в приложении

Экспорт: Приложение (используя библиотеку Gson в Kotlin) сериализует текущие дата-классы пользователя в JSON-строку. Конфиденциальные данные (настройки аккаунтов, токены) строго исключаются на этапе маппинга.

Импорт и Fault-Tolerance (принцип QR-кода):

Для обеспечения максимальной отказоустойчивости, парсер приложения работает по принципу "выживает сильнейший". Если пользователь вручную редактировал файл .fptools и допустил ошибку (например, не закрыл кавычку в 3-м шаблоне) — приложение не упадет и файл не будет отклонен.

Логика парсера Kotlin:

  1. Читаем объект data.
  2. Начинаем итерацию по массиву templates.
  3. Чтение каждого элемента обернуто в отдельный блок try-catch.
  4. Если 3-й элемент вызывает JSONException, исключение глушится, цикл переходит к 4-му элементу.
  5. В итоге приложение успешно импортирует 1-й, 2-й и 4-й шаблоны.
